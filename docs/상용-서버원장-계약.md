# 드림그룹 상용 서버 원장 계약 초안

상태: R3 구현 전 승인 필요
권장안: **드림그룹 Cloud Function/API가 최애돌 RS256 SSO 토큰을 JWKS로 검증하고 자체 HttpOnly 세션을 발급**

## 1. 권한 경계

- 최애돌 네이티브 앱만 로그인 토큰을 받는다.
- 드림그룹 웹 JavaScript는 토큰을 보거나 저장하지 않는다.
- 드림그룹 API는 검증한 `sub`를 내부 `account_id`에 매핑한다.
- 게임 진행, 일일 보상, RUN 완료, 시즌 결과를 확정하는 주체는 서버다.
- 클라이언트는 의도와 입력만 제출하고 계산 결과나 보상량을 신뢰값으로 제출하지 않는다.

## 2. 최소 원장

| 엔티티 | 식별자 | 불변조건 |
|---|---|---|
| `account_game_state` | `account_id` | 단일 현재 버전, 낙관적 잠금 `version` 증가 |
| `run_ledger` | `account_id + run_id` | 시작/완료 멱등, 완료 뒤 핵심 결과 불변 |
| `run_action_ledger` | `run_id + turn_no + action_id` | 같은 턴 중복 실행·중복 보상 금지 |
| `daily_ledger` | `account_id + kst_day + project_type` | 하루 1회 완료, KST 기준 |
| `reply_ledger` | `account_id + reply_id` | 서버가 `reveal_at` 계산, 1회 열람·보상 |
| `group_ledger` | `account_id + group_id` | 소유 RUN만 편성, 버전 충돌 차단 |
| `season_submission` | `season_id + account_id + submission_id` | 서버 계산 결과만 승점 반영 |
| `event_ledger` | `account_id + event_id` | 이벤트 이름·필드 허용목록, 중복 적재 거부 |

## 3. 최소 API

### 세션

- `POST /v1/session/exchange`
  - 네이티브가 bearer SSO 토큰으로 호출한다.
  - 서버는 `iss`, `aud`, `exp`, 서명, nonce 재사용을 검증한다.
  - 성공 시 `HttpOnly; Secure; SameSite=None` 세션 쿠키와 CSRF 토큰을 발급한다.
- `POST /v1/session/refresh`, `DELETE /v1/session`

### 저장과 RUN

- `GET /v1/state` → 서버 버전과 클라이언트 표시용 스냅샷
- `POST /v1/runs` → 서버가 `run_id`, 시드, 시즌, 규칙 버전을 발급
- `POST /v1/runs/{run_id}/actions`
  - `Idempotency-Key`, `expected_turn`, 사용자 선택을 받는다.
  - 서버가 성장·소모·이벤트·다음 손패를 확정한다.
- `POST /v1/runs/{run_id}/finish`
  - 마지막 처리 턴과 서버 상태를 검증해 카드·기억·답장 예약을 한 트랜잭션으로 기록한다.

### 일일·그룹·시즌

- `GET /v1/daily`, `POST /v1/daily/projects`, `POST /v1/daily/replies/{reply_id}/open`
- `PUT /v1/groups/{group_id}` (`If-Match: version` 필수)
- `POST /v1/seasons/{season_id}/submissions`
- `GET /v1/seasons/{season_id}/standings`

## 4. 충돌·멱등·복구

- 모든 mutation은 계정, 엔드포인트, `Idempotency-Key` 조합으로 결과를 최소 24시간 재생한다.
- `expected_version` 불일치는 `409 state_conflict`와 최신 스냅샷을 반환한다. 클라이언트가 자동 덮어쓰지 않는다.
- 오프라인에서는 이미 받은 RUN의 선택을 로컬 큐에 보관할 수 있지만 보상·완료 화면은 서버 확인 전 `확정 대기`로 표시한다.
- 기기 교체 시 서버 스냅샷만으로 카드·RUN·답장·그룹을 복구할 수 있어야 한다.
- 기존 localStorage 진행은 1회 가져오기 후보로만 취급한다. 계정당 한 번, 별도 `legacy_import` 원장과 운영 검토가 없으면 보상/경쟁 자산으로 승격하지 않는다.

## 5. 실패와 롤백

- RUN 완료 트랜잭션이 실패하면 카드·답장·보상 중 일부만 기록되면 안 된다.
- 배포 시 규칙 버전을 RUN에 고정해 진행 중 RUN이 새 밸런스로 바뀌지 않게 한다.
- 새 API 쓰기를 킬스위치로 막아도 기존 상태 읽기와 최애돌 앱 복귀는 가능해야 한다.
- 원장 스키마 변경은 expand → backfill → switch → contract 순서로 배포한다.

## 6. 승인해야 할 결정

1. 최애돌 RS256 SSO/JWKS 복제안을 드림그룹 인증 방식으로 채택할지
2. 서버 권한 턴 판정을 첫 베타부터 적용할지, 경쟁/시즌만 먼저 서버화할지
3. 기존 로컬 진행을 폐기할지, 계정당 1회 검증 가져오기를 허용할지
4. 푸시 발송 주체와 딥링크: 최애돌 서버가 `reply_ready` 원장을 읽어 발송할지

이 네 가지가 승인되기 전에는 네이티브·프로덕션 서버 변경을 시작하지 않는다.
