# 드림그룹 리텐션 제품 기준

작성일: 2026-08-04
제품 목표: **스탠드얼론으로도 반복 플레이할 가치가 충분하고, 최종적으로 최애돌의 강력한 리텐션 훅으로 확장 가능한 상용 게임**

## 0. 출시 순서와 현재 합격선

1. **현재 스코프 — 스탠드얼론 상용성:** 별도 웹 게임만으로 첫 진입, 정상 완주, 반복 육성, 카드·그룹 수집, D1 복귀가 충분히 재미있고 안정적이어야 한다.
2. **확장성 보존:** 계정, 저장소, 보상, 분석, 딥링크를 교체 가능한 경계로 유지해 최애돌 연동 때 핵심 게임 로직을 갈아엎지 않는다.
3. **최종 스코프 — 최애돌 실섭 통합:** 스탠드얼론 상용 후보가 검증된 뒤 SSO, 계정 귀속 원장, 앱 이벤트, 푸시, 본체 리텐션 실험을 연결한다.

따라서 최애돌 실섭 미연결은 현재 스탠드얼론 후보의 출시 차단 사유가 아니다. 다만 연동 경계를 게임 로직에 직접 결합하거나, 로컬 저장을 서버 저장처럼 소개하는 것은 허용하지 않는다.

## 1. 사용자가 겪어야 하는 핵심 루프

`최애 선택 → 첫 RUN 시작 → 선택으로 무대 완성 → RUN 카드·기억 획득 → 팬덤 프로젝트 약속 → 다음날 답장 확인 → 재육성·새 멤버 육성 → 그룹·시즌 완성`

기능 수나 한 판의 화려함은 성공 기준이 아니다. 아래 세 문장이 실제 사용자 행동으로 성립해야 한다.

1. **내 최애라서 시작한다.** 스탠드얼론에서는 최애를 빠르게 찾고 선택하며, 추후 최애돌 연동 시 기존 최애가 자연스럽게 이어진다. 실존 아이돌을 평가하는 대신 사용자가 만든 이번 RUN의 방향과 결과를 수집한다.
2. **내 선택의 결과라서 다시 키운다.** 첫 판은 완주를 배우되 자동승리처럼 보이지 않고, 이후에는 약속·방향·지원 카드·멘토 선택이 다른 결과와 카드를 만든다.
3. **팬덤과 남긴 약속 때문에 내일 돌아온다.** 팬덤 프로젝트와 답장은 장식 문구가 아니라 다음 RUN 보정, 미완결 약속 재도전, 시즌 기록으로 이어진다.

## 2. 이번 개발 배치

### R2 — 웹 게임 핵심 경험

- 첫 RUN 준비 화면은 `추천 방향 → 첫 약속 → 시작`만 기본 동선에 남기고, 지원 카드·멘토·대안 약속은 보유/다회차 때 점진적으로 연다.
- `팬 소통 준비도`와 `팬덤과의 인연`을 이름·설명·표시 위치에서 분리한다.
  - 팬 소통 준비도: 해당 RUN의 무대 준비 6영역 중 하나.
  - 팬덤과의 인연: 아이돌별로 누적되고 다음날 답장·재육성에 이어지는 관계 자산.
- 첫 RUN의 목적은 파이널 1위 보장이 아니라 **조작 학습과 카드 완성**이다. 관문 보호는 숨기지 않고 이유를 알려주며, 사용자의 추천 선택을 배신하는 반복 꼴찌를 막는다.
- 결과 화면의 우선순위는 `완주 요약 → 내일 답장/오늘 프로젝트 → 완성한 RUN 카드 → 팬덤과 남긴 장면 → 다음 성장 목표` 순서로 고정한다.
- D1 훅을 보지 못한 채 홈으로 빠지거나, 다음 행동 CTA가 두 개 이상 동급으로 경쟁하지 않게 한다.
- 첫 그룹 전 D1 답장은 최애 전용 재육성 보상을 보존하면서도, 다음 멤버 RUN의 시작 보정을 열어 그룹 진행과 충돌하지 않게 한다.

### R3 — 최종 최애돌 앱인앱 통합 관문

- 네이티브 `web_token`을 서버에서 검증해 HttpOnly 세션을 만든다. 토큰은 URL, postMessage, 웹 저장소에 넣지 않는다.
- 진행·RUN 원장·일일 완료·시즌 결과는 인증 계정에 귀속한다. localStorage는 오프라인 캐시와 복구 보조로만 쓴다.
- iOS/Android가 `DREAM_GROUP_READY`, `DREAM_GROUP_EVENT`를 동일한 허용목록과 스키마로 처리한다.
- 시즌/경쟁전 판정과 보상은 서버 권한으로 이전한다. 그 전에는 `고스트 리그`로만 표시한다.
- 장애 시 드림그룹 진입 슬롯을 원격으로 끌 수 있고, 마지막 안정 버전으로 즉시 롤백할 수 있어야 한다.

R3는 정적 웹 저장소만으로 완료할 수 없다. 스탠드얼론 상용 후보 검증 후 별도 승인과 담당 개발자 합의로 진행한다.

## 3. 계측 퍼널과 베타 판정

현재 스탠드얼론 베타는 익명 설치 식별자와 저장 가능한 동의 기반 분석 식별자로 코호트를 계산한다. 최애돌 통합 베타부터는 **인증된 최애돌 계정**을 분모로 전환한다. 일일 경계는 현재 KST로 고정하되, 글로벌 베타 전에 사용자 현지 시각 적용 여부를 결정한다.

| 단계 | 필수 이벤트/원장 | 2주 베타의 가설 기준 |
|---|---|---|
| 진입 | 랜딩 노출·`app_open`; 통합 후 슬롯 클릭·`context_received` | 스탠드얼론 유입과 앱 컨텍스트 성공률을 분리 측정 |
| D0 활성화 | `run_start` | 진입자의 60% 이상이 첫 RUN 시작 |
| 첫 가치 경험 | `fandom_first_contact`, `run_finish` | 시작자의 70% 이상 첫 RUN 완주 |
| 내일 약속 | `daily_complete` | 완주자의 40% 이상 당일 팬덤 프로젝트 완료 |
| D1 게임 복귀(현재 1차) | `daily_reply_open`, D1 `run_start` | 설치 코호트 기준 답장 도달·열람·다음 육성 전환을 측정하고 목표치는 파일럿 분포 후 확정 |
| D1 본체 복귀(통합 후 1차) | 최애돌 본체의 D1 출석 또는 핵심 활동 | 노출 전 계정 단위 무작위 배정, ITT 기준 홀드아웃 대비 효과와 신뢰구간으로 판정 |
| 반복 육성 | `retrain_started`, 다음 `run_finish` | 활성자의 7일 내 자발적 2회차 시작률 25% 이상 |
| 장기 목표 | `group_debut`, `season_brief_open` | 코호트별 도달률과 소요 일수를 관측해 정식 목표 확정 |

표본이 작아 통계적으로 판정할 수 없으면 성공으로 간주하지 않는다. 사전에 자격 코호트, 제외조건, 최소 표본수, 14일 관측창을 고정하고 효과 크기와 신뢰구간을 함께 보고 베타 연장 또는 노출 확대를 결정한다. 위 수치는 현재 성과 예측이 아니라 베타를 시작하기 위한 가설 기준이며, 표본수 계산과 PM 승인 전에는 출시 KPI로 확정하지 않는다.

### 가드레일

- 스탠드얼론 저장 완료율 99.9% 이상, 중복 `run_id` 보상 0건
- 통합 후 인증 컨텍스트 성공률 99.5% 이상
- 크래시 없는 세션 99.5% 이상
- 첫 RUN 시작 후 60초 이내 이탈, 결과 전 이탈, D1 답장 미노출을 별도 경보
- 실존 아이돌 능력 서열화, 본체 하트/투표 경제 쓰기, 토큰 노출은 0건이어야 함

## 4. 요구사항-구현-증거 추적

| 요구사항 | 현재 구현 | 완료 증거 | 판정 |
|---|---|---|---|
| 최애로 바로 시작 | 검색·선택, `DREAM_GROUP_CONTEXT` 확장점 | 스탠드얼론 첫 선택 테스트; 통합 후 iOS/Android 계정 fixture | 웹 검증 필요 / 통합 준비 |
| 초보 첫 RUN 완주 | 첫 관문 보호, 추천 방향·손패 | 고정 시드 UI 흐름 + 1만 판 시뮬레이션 + 비게이머 테스트 | 개선 필요 |
| 선택이 다른 결과 생성 | RUN 방향·약속·지원·멘토·시즌 에디션 | 전략별 결과 분포와 불변 `run_id` 테스트 | 부분 완료 |
| 팬덤 유대와 D1 답장 | 팬덤 프로젝트·KST 답장·다음 RUN 보정 | 브라우저 D0→D1 지속·답장→재육성 전환 | 웹 완료 / 실사용 검증 필요 |
| 카드·그룹·시즌 수집 | RUN 카드·버전 앨범·그룹·시즌 | 저장 복구·중복 방지·시즌 회귀 | 웹 완료 / 복구 QA 필요 |
| 공정한 경쟁 | 고스트 리그 고지 | 스탠드얼론은 고스트임을 명시; 통합 경쟁은 서버 판정 | 고스트만 허용 |
| 안전한 상용 운영 | 이벤트 허용목록, 로컬 복구 | 배포 모니터링·롤백 훈련·데이터 내보내기/초기화 | 개선 필요 |

## 5. 출시 차단과 종료 규칙

### 스탠드얼론 상용 후보 `NO-GO`

다음 중 하나라도 남으면 스탠드얼론 공개 후보로 승인하지 않는다.

1. 첫 진입부터 첫 RUN 완주·저장·재접속까지 막는 P0 또는 핵심 퍼널 P1
2. 진행 유실, 중복 보상, 저장 복구 실패, 데이터 초기화/내보내기 부재
3. 고스트 경쟁을 실제 사용자 대전처럼 오인시키는 표현 또는 클라이언트 점수를 공정한 공식 순위처럼 소개
4. 주요 모바일 화면비·오디오·백그라운드 복귀·지원 언어의 출시 후보 검수 미완료
5. 이미지·음원 권리, 개인정보/분석 고지, 오류 관측, 롤백 절차 미완료

### 최애돌 통합 공개 `NO-GO`

다음은 최종 앱인앱 통합 단계에서 추가로 적용한다.

1. 인증 없는 진입, 계정 귀속 저장 미완료, 토큰/개인정보 노출
2. 진행 유실·중복 보상·클라이언트 권한 시즌 판정
3. iOS/Android 웹뷰·앱 복귀·푸시/딥링크·지원 언어 실기기 미검수
4. 본체 핵심 지표를 해치거나 본체 보상 경제를 오염시키는 연동

개발 검증은 한 배치당 `사전검증 1회 → 구현 → 고정 후보 검증 1회 → P0/P1 수정 → 확인 1회`로 끝낸다. P2/P3는 백로그로 보내며 루프를 다시 열지 않는다. 두 번째 확인 뒤에도 P0/P1이 남으면 배포하지 않고 사용자에게 선택을 요청한다.

## 6. 롤백과 관측

- 배포 단위마다 커밋 SHA와 웹 자산 버전을 기록한다.
- 앱 홈 진입 슬롯은 원격 설정으로 즉시 숨길 수 있어야 한다.
- 서버 스키마는 하위 호환을 유지하고, 새 원장 쓰기를 끈 뒤에도 읽기와 기존 게임 복귀가 가능해야 한다.
- 출시 후 24시간은 인증 실패, 저장 실패, 첫 RUN 완주율, D1 답장 노출을 집중 관측한다.
- 가드레일 위반 또는 P0 발생 시 노출 중단 → 마지막 안정 버전 롤백 → 원장 정합성 점검 순으로 대응한다.
